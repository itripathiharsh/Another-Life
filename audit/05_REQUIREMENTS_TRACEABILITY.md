## 2. Specification Conflict Analysis

During our review, one explicit specification conflict was identified:

### Conflict: Database Technology & Save Strategy
- **Conflict Source:** `TECHNICAL_IMPLEMENTATION_PLAN.md` §4, §25 mandates **PostgreSQL** as the primary persistent database for all games, players, events, and content.
- **Counter-Specification:** `CLAUDE.md` Rule 1 (Strict D-Drive Rule) and `TECHNICAL_IMPLEMENTATION_PLAN.md` §39 allow simplifying MVP persistence to deterministic versioned file-based snapshots under the repository on Drive D.
- **Architectural Resolution:**
  The current implementation uses versioned JSON snapshot files (`.data/saves/*.json`), which complies with the D-Drive Rule and avoids external database server dependencies during early local development. However, the schema lacks relational referential integrity, and atomic file replacement (`tempfile` + `rename`) is missing.
- **Recommendation:** Maintain file-based snapshots for local development, but implement atomic writes (`atomic-write`) and prepare Prisma/PostgreSQL migration schemas for server deployment.
